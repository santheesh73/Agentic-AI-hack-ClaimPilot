# AI Disclosure

This project was built for the Product Space Agentic AI Hackathon (Unstop).

**Directed by the human author:** the product idea, the problem framing, the six-check appeal rubric and its verdict rules, the decision to verify every citation in code rather than trust the model, the state-machine design, the database schema, the UI structure, and all product and scope decisions (including what's explicitly out of scope: legal advice, auto-filing, OCR of scanned PDFs).

**Generated with Claude Code, under the author's direction and review:** the TypeScript/Next.js implementation — the ingest pipeline, the citation verifier and its tests, the deadline engine and its tests, the agent tools and prompts, the API routes, and the UI components.

**Sample policy document (`samples/policy.pdf`):** the original plan was to use a real, publicly published insurer's policy wording PDF. That specific document was unreachable from the build environment's network and was not supplied in time, so Claude Code authored a substitute policy wording document instead of leaving the sample data missing. It is grounded in real regulatory language, not invented from scratch: IRDAI (the Indian insurance regulator) mandates a standard set of exclusion clauses — the same clause codes and near-identical wording (Excl01 "Pre-Existing Diseases", Excl08 "Cosmetic or Plastic Surgery", etc.) — verbatim across all Indian health insurers. The three sample rejection letters (`samples/letter_a.txt`, `_b.txt`, `_c.txt`) and their expected verdicts in `evals/cases/*.json` were written against this document's actual clause text and page numbers, and verified by running the real extraction/assessment/drafting/verification/red-team pipeline against it with live model calls. Before relying on this for the hackathon submission, the author should either swap in a genuine insurer PDF and re-verify the eval results, or disclose in the submission that the sample policy is an authored stand-in.

**Bugs found and fixed by running the real pipeline against real data:** two defects in the verdict/pause logic (`lib/agent/machine.ts`) were caught only once the agent was actually run end-to-end with a real document and real model calls, not by code review or unit tests alone — see the git log for specifics. This is called out because it's a concrete example of where "the code compiles and the unit tests pass" was not sufficient evidence that the product worked.
