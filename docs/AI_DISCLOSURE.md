# AI Disclosure

This project started as a build for the Product Space Agentic AI Hackathon (Unstop), then continued as a hardening/portfolio pass toward production quality.

**Directed by the human author:** the product idea, the problem framing, the six-check appeal rubric and its verdict rules, the decision to verify every citation in code rather than trust the model, the state-machine design, the database schema, the UI structure, and all product and scope decisions (including what's explicitly out of scope: legal advice, auto-filing, OCR of scanned PDFs).

**Generated with Claude Code, under the author's direction and review:** the TypeScript/Next.js implementation — the ingest pipeline, the citation verifier and its tests, the deadline engine and its tests, the agent tools and prompts, the API routes, and the UI components.

**Sample policy document (`samples/policy.pdf`):** the original plan was to use a real, publicly published insurer's policy wording PDF. That specific document was unreachable from the build environment's network and was not supplied in time, so Claude Code authored a substitute policy wording document instead of leaving the sample data missing. It is grounded in real regulatory language, not invented from scratch: IRDAI (the Indian insurance regulator) mandates a standard set of exclusion clauses — the same clause codes and near-identical wording (Excl01 "Pre-Existing Diseases", Excl08 "Cosmetic or Plastic Surgery", etc.) — verbatim across all Indian health insurers. The three sample rejection letters (`samples/letter_a.txt`, `_b.txt`, `_c.txt`) and their expected verdicts in `evals/cases/*.json` were written against this document's actual clause text and page numbers, and verified by running the real extraction/assessment/drafting/verification/red-team pipeline against it with live model calls. Before relying on this for the hackathon submission, the author should either swap in a genuine insurer PDF and re-verify the eval results, or disclose in the submission that the sample policy is an authored stand-in.

**Bugs found and fixed by running the real pipeline against real data:** three defects were caught only once the agent was actually run end-to-end with a real document and real model calls, not by code review or unit tests alone — two in the verdict/pause logic (`lib/agent/machine.ts`: `decideVerdict` never produced WEAK when the cited clause genuinely held and nothing overrode it; the `AWAITING_USER` pause only fired on an "unknown" answer to C5, not "no", which means the same thing), and one in the citation parser (`lib/agent/verify.ts`: the model formats citations as `[cite: E1, E2]` rather than the requested `[cite:E1][cite:E2]`, which silently zeroed out citation verification on otherwise well-cited drafts). This is called out because it's a concrete example of where "the code compiles and the unit tests pass" was not sufficient evidence that the product worked — all three were found only by running it for real.

**The hardening pass** (branch `hardening`, `docs/AUDIT.md`/`docs/KNOWN_ISSUES.md`) found and fixed several more real bugs the same way — by actually exercising the code, not by inspection: a PostgREST `.update().order().limit()` no-op that silently marked every draft version's `approved_at` instead of just the latest one; the same citation-stripping regex bug independently re-drifted in two more places (the printable letter page, the simulate route) after being fixed once; an `AskUserDialog` that got permanently stuck in "Submitting…" if the network call threw; missing Vercel file-tracing that would have 500'd the "Load sample case" buttons in production; a genuine upstream `@ai-sdk/anthropic`/`@ai-sdk/google` dependency version conflict; and — the clearest example — `lib/ingest/pdf.ts`'s `parsePdf()` crashing on a real Node `Buffer` (a Buffer passes `instanceof Uint8Array` but `unpdf` explicitly rejects one), which would have broken both the live sample route and `pnpm eval` outright, caught only when a route-handler test exercised the real `samples/policy.pdf` instead of a mock. See `git log` on `hardening` for the full list with commit messages explaining each.

**What's still an authored placeholder, not a human review pass:** this disclosure document itself, `docs/RESUME.md`'s interview answers, and the README's limitations/roadmap sections were all written directly by Claude Code to be accurate to the actual codebase, not reviewed and personalized by the author yet.
